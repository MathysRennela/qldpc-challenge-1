# [[450,8,28]] weight-6 bivariate-bicycle code with a 3D torus-surface layout

## Direction & hypothesis

Target cell: `weight-6 × unrestricted`. The search samples moderate-size bivariate-bicycle codes, whose six-term CSS checks provide a sparse family with nontrivial rate. For the 3D-layout trial, the two periodic group blocks are embedded as separated torus surfaces in Euclidean 3-space. This is a 3D coordinate layout, not a claim that the code is a bulk 3D-local code; the verifier measures the long supports directly.

## What was searched

Drew 800 random pairs of three-term supports `A` and `B`, with `l,m` independently sampled from `5..20`. Kept codes with `100 <= n=2lm <= 700` and check weight at most 6. Screened with 250 NumPy RIS trials per candidate, requiring `k >= 4` and screen value `d >= 8`, then retained the sampled Pareto frontier. Finalists were packaged with the kit's witness search. The first completed package was this `Z_15 x Z_15` code. The bounded run timed out while packaging later finalists; none of those screen-only records is presented as validated.

## Evidence trail

The `qldpc submit` package claims `d <= 28` (X witness 28, Z witness 28), an upper bound, not an exact distance. Against upstream commit `34c5c14e`, the final trusted candidate validator returned `passed: true`: CSS/layout checks passed, no lighter logical was found in 8,000 RIS trials (seed `1651688263`), there is no exact or graph-equivalent duplicate, and the code advances the `weight-6 × unrestricted` board cell. Literature novelty is unverified.

The verifier reports a D=3 layout with minimum site spacing 1, interaction radius 25.7178, and bounding box `[25.7641, 25.906, 4.7834]`. The D=3 geometric efficiency evaluated at the witness upper bound is about `8.28e-5`; this is not a geometric-efficiency record. The radius reflects the selected BB supports on the embedded torus surfaces.

## Dead ends

An earlier, non-3D sample claimed `[[450,4,32]]`; the contributor CLI's 20,000-trial search found a weight-30 logical instead, and the resulting `[[450,4,30]]` is already an exact board duplicate. It was not submitted. The present candidate is a different `Z_15 x Z_15` code and has its own current-board gate result above.

## Tools

GPT-6 Luna in Zed; the research kit's `sample_bb`, `screen`, `pareto_frontier`, and `make_submission`; `./qldpc submit` for the final package; and the trusted `verify/validate_candidate.py` from upstream commit `34c5c14e`. The BB family reference is Bravyi et al., arXiv:2308.07915; this polynomial pair's literature novelty remains unverified. Screening used NumPy (250 trials); the CLI witness search used 20,000 RIS trials. No exact-distance certification was run. The CLI attempted circuit generation but skipped the circuit tier because the Z-memory DEM had 504,671 mechanisms, above the 25,000-mechanism cap.

## Reproduction

```python
from bb import build_bb
HX, HZ = build_bb(
    15, 15,
    A_terms=[(13, 13), (14, 6), (5, 3)],
    B_terms=[(5, 0), (12, 1), (9, 6)],
)
```

The layout embeds qubit `(block, i, j)` at a torus-surface point. With `r = 1/(2 sin(pi/m))`, `R = r + 1/(2 sin(pi/l))`, and `gap = 2r + 1`, set `theta = 2pi*i/l`, `phi = 2pi*j/m`, `R_block = R + block*gap`, and

`((R_block + r*cos(phi))*cos(theta), (R_block + r*cos(phi))*sin(theta), r*sin(phi))`.

All coordinates are uniformly scaled so the minimum pairwise spacing is 1. The code is packaged with confidence `upper_bound`; the 3D layout's measured check diameters, rather than an assumed locality cap, determine its reported geometric score.
