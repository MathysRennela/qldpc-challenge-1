# [[490,6,32]] — weight-6 bivariate bicycle over Z_35 x Z_7

## Direction & hypothesis

Target cell: `unrestricted / weight-6`. At `k >= 6`, `d >= 32` and check weight
at most 6 the board's smallest code was `n = 540` (`codes/540-8-32.json`), and
at `k = 6` specifically only `codes/630-6-36.json` (n = 630) and
`codes/700-6-32.json` (n = 700) qualified at all. A weight-6 code at
`n = 490, k = 6, d = 32` is therefore both the smallest of that group and a
strict domination of `codes/700-6-32.json`, which has the same k, d and weight
at 210 more qubits. Bivariate bicycle codes give weight 6 for free when
`|A| = |B| = 3`, so the sweep searched small group orders against the
divisibility condition of arXiv:2502.17052v4; `n = 490 = 2 * 35 * 7` is one
such order.

## What was searched

Bivariate bicycle codes `H_X = [C_A | C_B]`, `H_Z = [C_B^T | C_A^T]` over
`Z_p x Z_q` with `|A| = |B| = 3`, so every check has weight 6 and
`n = 2 * p * q`. Candidates were kept only when the group order satisfied the
divisibility condition of arXiv:2502.17052v4. The sweep's run count and seeds
were not preserved with the candidate, so no sweep size is claimed here.
Screening was on `(n, k, d, w)`: anything already on the board's weight-6
frontier at those parameters was dropped.

## Evidence trail

- `verify/qldpc_verify.py codes/490-6-32.json` returns `ok: true`, all 14
  checks. Computed `rank H_X = rank H_Z = 242`, so
  `k = 490 - 242 - 242 = 6`; `H_X H_Z^T = 0`; Tanner graph connected with
  girth 6 on both sides; max check weight 6; weight class `weight-6`,
  locality class `unrestricted`.
- `verify/validate_candidate.py` on the submitted bytes returned
  `passed: true` (seed 92717841): `refuted: false` after 8000 RIS trials per
  side, `exact_duplicate_of: null`, `wl_equivalent_of: null`,
  `board_advancing: true`, `dominated_by: []`. The `qldpc_verify.py` pass ran
  its own refutation independently (seed 1325898944) and also found no lighter
  logical.
- **The distance was corrected before submission.** The campaign claimed
  `d = 34`. An earlier validator run refuted that with a weight-32 X-side
  logical, verified to commute with the Z checks and to lie outside the row
  space of the X checks. That witness is the lightest known and is the one
  shipped. The Z side witness is weight 36.
- **The claim is a witness-backed upper bound, not a certificate.** Both sides
  carry `confidence: upper_bound`, so this states `d <= 32`; nothing here
  proves that no lighter logical exists.

## Dead ends

The claimed `d = 34` was the dead end: refuted at weight 32. Correcting the
claim to the lightest known witness is what makes the code submittable, and
the corrected value still advances the board. A second, different code from
the same sweep also lands at these corrected parameters; only one of them can
occupy `codes/490-6-32.json`, and it is this one. Siblings from the same
sweep: `[[574,6,38]]` shipped unchanged in its own PR, `[[618,4,46]]` ships
corrected in another, and `[[450,4,38]]` (which would correct to
`[[450,4,30]]`) is not submitted because it no longer dominates anything once
corrected.

## Reproduction

`G = Z_35 x Z_7`, with group element `(i, j)` indexed as `7 * i + j`, so
`|G| = 245` and `n = 2 * |G| = 490`. With `C_S` the `245 x 245` matrix
`(C_S)_{g,h} = 1` iff `h - g` lies in `S`:

- `A = {(0,0), (8,3), (14,2)}`
- `B = {(21,2), (21,6), (34,1)}`
- `H_X = [C_A | C_B]`, `H_Z = [C_B^T | C_A^T]`

Building those two matrices from the supports above reproduces the check lists
checked in at `codes/490-6-32.json`.
