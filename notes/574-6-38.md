# [[574,6,38]] — weight-6 bivariate bicycle over Z_7 x Z_41

## Direction & hypothesis

Target cell: `unrestricted / weight-6`. No entry in that cell with `k >= 6`
had ever reached `d >= 38` — the best were `codes/630-8-36.json`,
`codes/672-8-36.json` and `codes/630-6-36.json`, all at `d = 36`. The four
entries holding the `n = 608..700` band at small `k` (`codes/608-2-36.json`,
`codes/618-4-38.json`, `codes/630-6-36.json`, `codes/700-6-32.json`) are
weight-6 too, so a weight-6 code at `n = 574, k = 6, d = 38` would beat all
four at once on `n` or on `d`. Bivariate bicycle codes give weight 6 for free
when `|A| = |B| = 3`, so the sweep searched small group orders against the
diversibility condition cited in `provenance.references` instead of inventing
a new family.

## What was searched

Bivariate bicycle codes `H_X = [C_A | C_B]`, `H_Z = [C_B^T | C_A^T]` over
`Z_p x Z_q` with `|A| = |B| = 3`, so every check has weight 6 and
`n = 2 * p * q`. Candidates were kept only when the group order satisfied the
divisibility condition of arXiv:2502.17052v4; `n = 574 = 2 * 7 * 41` is one
such order. The sweep's run count and seeds were not preserved with the
candidate, so no sweep size is claimed here. Screening was on `(n, k, d, w)`:
anything already on the board's weight-6 frontier at those parameters was
dropped.

## Dead ends

Distance, not parameters, stopped the rest of this sweep. Three sibling
candidates — `[[490,6,34]]`, `[[450,4,38]]` and `[[618,4,52]]` — each screened
non-dominated, but each has a recorded refutation: a lighter logical of weight
32, 30 and 46 respectively exists on one side of each, verified directly
against their own check lists. Two of them are submitted in their own PRs at
those corrected distances, as `[[490,6,32]]` and `[[618,4,46]]`. The third
would become `[[450,4,30]]`, which dominates nothing once corrected, so it is
not submitted. This PR ships only the code whose claimed distance survived
refutation.

## Reproduction

`G = Z_7 x Z_41`, with group element `(i, j)` indexed as `41 * i + j`, so
`|G| = 287` and `n = 2 * |G| = 574`. With `C_S` the `287 x 287` matrix
`(C_S)_{g,h} = 1` iff `h - g` lies in `S`:

- `A = {(0,0), (1,39), (3,30)}`
- `B = {(0,0), (1,14), (3,20)}`
- `H_X = [C_A | C_B]`, `H_Z = [C_B^T | C_A^T]`

Building those two matrices from the supports above reproduces the check lists
checked in at `codes/574-6-38.json`.
