## Source and method

Inspected arXiv:2306.16400v1 (Lin--Pryadko, *Quantum two-block group algebra codes*) and the authors' public database at `github.com/QEC-pages/2BGA-codes`.
The public repository provides `abelian.zip`, `nonabelian.zip`, and `2BGA.gap`; this audit used the database contents from commit `403d194c3f98f0cadc236aecbc4a8b6139ccf23c`. Database rows use 1-based GAP element positions and omit the identity from the displayed supports.

The paper's exhaustive scope is connected binary 2BGA codes with total stabilizer weight `W <= 8`, group order at most 50 for abelian groups and at most 100 for non-abelian groups. The challenge has a larger `n <= 700` envelope, so these rows are a bounded literature baseline rather than a complete search of the current board's construction space.

## Reconstruction result

The database row

- `SmallGroup(32,21)`;
- non-identity supports `a=[2,3,17]`, `b=[7,22,31]`;
- paper parameters `[[64,18,8]]`, total weight `W=8`

was rebuilt with GAP and `research/kit/group_algebra.py`. After adding the identity and converting to zero-based table indices, the reconstruction has CSS commutation, `n=64`, `k=18`, and maximum check weight 8.

`research/reconstruct_2306_16400_64_18_8.py` packages both witnesses through `research/kit/submit.py`. The trusted validator returned:

- `passed: true`;
- `weight-8 x unrestricted`;
- `board_advancing: true`;
- no exact duplicate and no WL-equivalent duplicate;
- no lighter logical found in the gate's 5,060 RIS trials;
- repository distance claim remains `d <= 8` / `upper_bound`, despite the paper's exact `d=8` claim.

The staged JSON is local ignored working output under `research/candidates/`; it is not a board submission or durable prose artifact.

## Other high-value rows found by parameter comparison

The first database comparison against `codes/*.json` surfaced additional absent parameter sets worth reconstructing, subject to the same convention and provenance checks:

- abelian: `[[70,8,10]]`, `[[72,10,9]]`, `[[72,8,10]]`, `[[60,6,10]]`, `[[64,18,8]]`;
- non-abelian: `[[196,12,17]]`, `[[84,14,10]]`, `[[126,20,10]]`, `[[112,12,12]]`, `[[200,8,18]]`, `[[136,8,15]]`.

These are literature rows, not automatically new codes. Parameter-set absence is not sufficient for promotion: each row must be reconstructed, checked against the board's computed Pareto relation, and sent through the trusted validator with persisted witnesses.

`research/reconstruct_2306_16400_batch.py` rebuilt and packaged the four highest-priority rows. All four passed the trusted validator and were labelled board-advancing in the `weight-8 x unrestricted` cell:

These remain literature reconstructions with `upper_bound` distance confidence; literature novelty is not claimed. Staged JSON files remain local ignored working output under `research/candidates/`.

## Decision

This tranche confirms that the public 2BGA database is a productive, reproducible source of board-advancing baselines. Human review should choose which rows to promote, if any. Continue with the next candidates only after checking the four staged reconstructions and their provenance; do not promote any result into `codes/` or claim literature novelty without human review.
